# 江欢欢巡店管理系统 v2.0.1

可直接运行、可部署到 GitHub Pages 的完整单设备 PWA 源码。
本项目没有构建步骤，不依赖 CDN，不需要购买服务器。压缩包根目录就是网站根目录。

## 先打开检查

解压后双击 `index.html`，即可检查页面与基本保存功能。
要测试手机安装和离线缓存，请使用 HTTPS 部署网址，或在电脑上启动本地 HTTP 服务。

Windows：安装了 Python 的电脑可以双击 `start-preview.bat`。
Linux/macOS：运行 `bash start-preview.sh`。
本地网址为 `http://localhost:8080`。文件方式、本地服务和部署网址各自拥有独立数据。

## 已实现的功能

| 模块 | 功能 |
| --- | --- |
| 工作台 | 本周巡店、门店覆盖率、真实整改待办、岗位缺口、最近巡店 |
| 门店 | 预置22家门店与两品牌，新增、编辑、搜索、状态筛选、负责人、岗位编制 |
| 巡店 | 日期、巡店人、8项检查、真实评分、说明、最多6张照片、编辑、删除、CSV导出 |
| 整改 | 新增问题、巡店关联、负责人、期限、逾期判断、整改状态、复查结论、CSV导出 |
| 人员 | 档案、岗位、入职日期、在职/待分配/离职、门店调配历史、缺口统计、CSV导出 |
| 新店帮扶 | 14项装修与开业准备、培训、帮扶内容、开业日期、进度与后续计划 |
| 周报 | 按日期汇总巡店/整改/帮扶、本月开业门店、报货分析、每日计划、CSV/文本/打印PDF |
| 我的与数据 | 督导资料、完整JSON备份与恢复、持久存储申请、重置、PWA安装说明 |

业务记录初始为空，不伪造营业额、人员、巡店或整改数据。
默认门店名单来自之前的源码；周报栏目和14项装修进度参考你提供的督导周报表。
门店检查项为可编辑的通用初始配置，可在 `assets/js/data.js` 中调整。

## 部署到 GitHub

详细步骤见 [GitHub部署说明](docs/GITHUB_DEPLOY.md)。
关键点：把解压后的**文件内容**复制到仓库根目录，使根目录直接看到 `index.html`。
完整保留 `assets`、`icons`、`manifest.json` 和 `service-worker.js`。
推荐用 Pages 的 `Deploy from a branch`，选择 `main` 与 `/(root)`。
本次不包含对你的 GitHub 仓库的自动修改或发布。

## 数据如何保存

- 默认使用浏览器 IndexedDB 持久保存记录和压缩后的照片；不可用时尝试 localStorage。
- 保存失败会显示错误，不显示假“保存成功”。
- 同一浏览器、同一网址再次打开，会读取原数据。
- 手机和电脑各自保存数据。无账号服务器，无多人实时共享，无自动云同步。
- 数据备份是含照片的 JSON。导入前校验结构、记录关联、状态与日期，再确认覆盖。
- CSV 是用于 Excel 查看/整理的文字表格，不包含照片，也不能替代完整备份。
- 打印 PDF 使用浏览器的打印功能，在打印对话框选择“另存为 PDF”。
- 清理浏览器网站数据、删除浏览器配置或换网址会影响数据访问。建议定期导出完整备份。
- 人员手机号等录入资料保存在设备，源码中不附带你的业务记录或个人数据。

## 统计口径

- 本周为周一至周日，按设备本地日期计算。
- 门店覆盖率分母是“营业中”门店，分子是这些门店中本周至少巡店一次的数量。
- 检查分为已检查项平均分：合格100、待改善50、不合格0；未检查项不参与分母。
- 人员缺口为 `max(编制 − 该门店该岗位在职人数, 0)`。暂停营业门店不计入总缺口。
- 编制0表示暂未设置需求。待分配、离职人员不计入实际在岗人数。
- 逾期是期限早于今天且未完成，不将期限当天判为逾期。
- 周报保存的是生成当时的文本快照。后续修改业务记录不会悄悄改动旧周报。
- 报货量、酱料未报门店与前五名由人工填写，单位可选元/件/箱/公斤。系统没有接入收银和报货平台。

## 修改与验证

常规修改只需编辑对应 JS/CSS，不需要 npm 编译。
发布修改时同步提升 `service-worker.js` 的 VERSION，确保已安装应用能发现更新。

核心验证：

```bash
node tests/core.test.cjs
node tests/business.test.cjs
node tests/assets.test.cjs
node tests/search-input.test.cjs
```

浏览器验证需要开发工具 Playwright 和 Chromium；这是测试依赖，应用运行不需要。
先在项目父目录开启 `python3 -m http.server 8765`，然后指定项目网址：

```bash
APP_TEST_URL=http://localhost:8765/inspection-source/ node tests/browser.test.cjs
```

如果本地目录名称不同，将网址里的路径换成实际目录。详细验证结果见 `docs/VERIFICATION.md`。

## 旧版迁移

新版首次打开时，如果与旧版使用同一浏览器和同一站点来源，会尝试读取旧版 `db.inspection` 或 `inspection` 的巡店文字数据。
旧版未保存过的照片、人员、帮扶和周报无法恢复。迁移不会删除原旧版存储字段。

## 本版边界

这是完整的单设备业务源码与离线应用，不含后台服务、账户登录、角色权限、支付、云同步或正式原生 APK/IPA。
所有菜单与保存操作均有实现，没有假登录按钮或“即将上线”业务入口。
如以后增加多人共享，应接入真正的服务器、身份验证和数据库，不能把浏览器本地数据称为云数据库。
